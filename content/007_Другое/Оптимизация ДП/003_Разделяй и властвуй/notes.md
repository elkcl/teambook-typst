# Оптимизация ДП методом «разделяй и властвуй»

Источник: https://peltorator.org/posts/divide_and_conquer_optimization/

Типичная динамика по числу групп:

$$
\operatorname{dp}[k][n]
 = \min_{i < n}
   \left(\operatorname{dp}[k - 1][i] + w(i, n)\right).
$$

`w(i, n)` — стоимость последней группы, а `opt[k][n]` — оптимальный `i` для состояния `dp[k][n]`. Обозначения границ можно сдвинуть на единицу без изменения метода.

## Главное условие

Нужна монотонность оптимального раздела:

$$
\operatorname{opt}[k][i]
\le \operatorname{opt}[k][i + 1].
$$

То есть при движении правой границы вправо оптимальная точка разбиения не движется влево. Это условие надо доказать для конкретной стоимости; без него ограничение диапазона кандидатов может отбросить правильный ответ.

## Рекурсивный расчёт строки

Для фиксированного `k` считаем одну строку `dp[k]`. Если известно, что для всех `i` оптимум лежит между `L` и `R`, середину можно вычислить перебором только этого диапазона. Затем условие монотонности сужает диапазоны для левой и правой половин.

```cpp
void calc(int k, int il, int ir, int optl, int optr) {
    if (il >= ir) {
        return;
    }

    int im = (il + ir) / 2;
    dp[k][im] = INF;
    int best = -1;

    for (int j = optl; j <= min(im, optr); j++) {
        auto value = dp[k - 1][j] + cost(j, im);
        if (value < dp[k][im]) {
            dp[k][im] = value;
            best = j;
        }
    }

    calc(k, il, im, optl, best);
    calc(k, im + 1, ir, best, optr);
}
```

Вызов для строки обычно имеет вид `calc(k, 0, n, 0, n)`. Реальные границы и недопустимые состояния зависят от того, сколько элементов должно быть в каждой из `k` групп.

## Сложность

Наивный переход одной строки занимает `O(n^2)`. Оптимизация разделяй-и-властвуй обычно даёт `O(n log n)` на строку и `O(K n log n)` для `K` строк, при `O(n)` или `O(Kn)` дополнительной памяти — в зависимости от того, нужно ли хранить все ответы.

Если стоимость позволяет получить более сильную структуру, например монотонность через условие Моне, могут существовать и более быстрые оптимизации. Но для данного метода достаточно доказать монотонность `opt`.
