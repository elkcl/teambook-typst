# Team Reference

Справочник собирается скриптом `./build`. Он читает `config.json`, находит файлы в `content/` и компилирует `main.typ` в PDF.

Нужны `typst`, `jq` и `find`. Для режима `tour` ещё `clang-format`: им код временно сжимается под узкую колонку. Исходники в репозитории при этом не меняются.

## Сборка

Из корня репозитория:

```bash
./build config.json
```

Режим берётся из поля `mode` в конфиге. Сейчас там `tour`, поэтому команда выше пишет компактный справочник в `notebook.pdf`.

Явно:

```bash
./build config.json tour
./build config.json book
```

Аргумент режима перекрывает `mode` в конфиге.

| Режим | Куда пишет | Что получается |
| --- | --- | --- |
| `tour` | `output_file`, сейчас `notebook.pdf` | Альбомный A4, три колонки. C++ прогоняется через `.clang-format.tour`: ширина 50, отступ 2 пробела, без пустых строк, скобки у однострочных `if`/`for` снимаются. Заметки печатаются только у разделов без кода. |
| `book` | `book_output_file`, сейчас `book.pdf` | Портретный A4, одна колонка. Код как в репозитории (`.clang-format`): ширина 80, отступ 4 пробела, скобки у однострочных операторов остаются. Над кодом печатается непустой `notes.md`. Каждый алгоритм начинается с новой страницы, заголовок раздела остаётся на странице его первого алгоритма. |

Имена выходных файлов и режим по умолчанию задаются в `config.json`: `mode`, `output_file`, `book_output_file`. Туда же вынесены название, команда, вуз, состав и дата на титуле.

## Как лежит материал

```
content/preamble.hpp
content/<раздел>/<алгоритм>/code.hpp
content/<раздел>/<алгоритм>/notes.md
```

`preamble.hpp` — общие алиасы, макросы и константы. У алгоритма файл кода называется `code` с исходным расширением (`.hpp`, `.cpp`, `.py`, `.txt`). Заголовок в PDF берётся из имени папки, в нём можно писать разметку Typst. Формульный раздел может состоять из одного `notes.md`.

Порядок разделов в PDF — это порядок, в котором `find` обходит `content/`, без дополнительной сортировки.

## Тесты

Нужны CMake 3.24+ и компилятор C++17. Google Test 1.16.0 скачивается сам при первой конфигурации. Каталог сборки — `cmake-build/`, в репозиторий он не попадает.

Из корня репозитория:

```bash
cmake -S . -B cmake-build
cmake --build cmake-build
ctest --test-dir cmake-build --output-on-failure
```

Первая команда готовит сборку, вторая компилирует `algo_tests`, третья прогоняет все тесты. Повторно достаточно последних двух, если `CMakeLists.txt` не менялся.

Один алгоритм — по имени набора. Имена латинские, список печатает сам бинарник:

```bash
./cmake-build/algo_tests --gtest_list_tests
ctest --test-dir cmake-build --output-on-failure -R '^Grafy_HLD\.'
./cmake-build/algo_tests --gtest_filter='Grafy_HLD.*'
```

`-R` у `ctest` — регулярное выражение по полному имени теста (`Grafy_HLD.Stub`). `--gtest_filter` — шаблон Google Test: `*` — любая строка, несколько шаблонов разделяются `:`.

Тест алгоритма лежит в `tests/<тот же путь, что в content>/test.cpp`. В `content/` его класть нельзя: `./build` подхватит лишний файл и сломает раздел в PDF. Для нового `code.hpp` заглушка создаётся так, уже написанные тесты скрипт не перезаписывает:

```bash
python3 tests/gen_stubs.py
```

### Как дописать тест

Заглушку в `test.cpp` заменяют обычными проверками Google Test. Первый аргумент `TEST` — имя набора, его оставляют как в заглушке: по нему фильтруется прогон.

`code.hpp` подключают из анонимного пространства имён. Все тесты линкуются в один `algo_tests`, а в сниппетах повторяются `dfs`, `main` и глобальные переменные. Анонимное пространство имён оставляет эти имена внутри одного `.cpp`. `preamble.hpp` подключают снаружи: там общие алиасы.

```cpp
#include <gtest/gtest.h>

#include "content/preamble.hpp"

namespace {
#include "content/Матеша/Бинарное возведение (без рекурсии)/code.hpp"
}

TEST(Matesha_Binarnoe_vozvedenie_bez_rekursii, PowersOfTwo) {
    EXPECT_EQ(binpow(2, 10), 1024);
    EXPECT_EQ(binpow(2, 0), 1);
}
```

Дальше пересобрать и прогнать этот набор:

```bash
cmake --build cmake-build
ctest --test-dir cmake-build --output-on-failure -R '^Matesha_Binarnoe_vozvedenie_bez_rekursii\.'
```

Если сниппет ссылается на тип, которого в файле нет, его объявляют в тесте до `#include` кода. У HLD это `SegmentTree`. Сниппет из голых операторов, как решето Эратосфена, так не подключается: в тесте его оборачивают в функцию.
